# Estimation policy

Estimate according to the work's uncertainty and output.

## Chore

Estimate normally when an estimate is useful. A Chore is already specific and
low variance, so it stays in the fast lane and bypasses bundle validation.

## MiniProject

Estimate the complete improvement, including behavior, verification, integration,
and release readiness. Implementation may use several small changes; do not turn
those changes into separately estimated board items.

## Discovery

Set a time box instead of an implementation estimate. The commitment is to produce
the named decision artifact and terminal outcome within that investment boundary.
If more Discovery is required, state the next question and set a new explicit time
box rather than silently extending the work.

## Project

Do not present one delivery estimate while the Project still contains unresolved
Discovery. Sequence the known work, resolve the load-bearing questions, and estimate
the resulting MiniProjects and Chores. Communicate remaining uncertainty rather than
hiding it inside a precise total.
